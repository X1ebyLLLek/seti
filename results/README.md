## Первая серия и найденный дефект

В серии `experiments-20261026-043134` (код `f0aecfc`) одно сообщение из 120 не было
доставлено: `star/run-01/messages.csv`, отправитель 3 → получатель 6, `status=failed`,
4 попытки, ошибка «recipient record not found in DHT» (журнал узла 3 в `node_logs.zip`).
Причина: запись получателя была опубликована, пока сеть ещё собиралась, а узлы,
присоединившиеся позже и оказавшиеся ближе к ключу, до переопубликования (90 с) записи
не имели; инициатор сам хранил копию, но поиск значения не учитывал собственное хранилище.

Исправление шло в три шага, каждый подтверждён тестом или прогоном:

1. `902f68c` — передача записи новому ближайшему узлу при добавлении его в таблицу и учёт
   собственной копии при `FIND_VALUE`; промежуточная серия на этой версии доставила 80/80 сообщений.
2. `c17cafa` — проверка из чистого клона показала нестабильный тест (1 из 12): если bucket
   хранителя полон, новый узел в таблицу не попадал и записи не получал. Передача стала
   выполняться при любом первом наблюдении узла, как в статье Kademlia; у теста исправлено
   непроверенное предусловие.
3. `5ebcc62` — приёмка после шага 2 показала записи на 9 узлах из 15: передавали и узлы с
   разреженным видом на окрестность ключа. Теперь передаёт только узел, сам входящий в R ближайших
   к ключу. Итоговые приёмка и серия выполнены на этой версии.

Серия до исправления сохранена как свидетельство. В её таблицах (`analysis/tables.md`)
недоставленное сообщение сначала входило в статистику задержек — эта ошибка обработки
исправлена в `902f68c`, таблицы пересчитаны (`analyze.py`), сообщение указано отдельно.
Промежуточные прогоны версий `902f68c` и `c17cafa` есть в истории git (коммит `558ac33`).

## Структура каталога прогона

| Файл | Содержание |
|---|---|
| `run_meta.json` | версия кода, время старта, seed, N, k, ALPHA, R, тайм-ауты, схема |
| `bootstrap_graph.json` | bootstrap-граф (кому какие адреса выданы) |
| `tables.json`, `table_sizes.csv` | выгрузка k-bucket всех узлов после сходимости |
| `convergence_rounds.csv` | контрольные раунды сходимости |
| `non_degeneracy.json` | проверка критериев раздела 6 ТЗ |
| `lookups.csv` | контрольные lookup: инициатор, цель, была ли цель в таблице, RPC, итерации, опрошенные узлы |
| `storage_failure.csv` | отказ хранителя и повторный `FIND_VALUE` |
| `intermediate_failure.csv` | отключение промежуточного кандидата во время lookup |
| `messages.csv` | сообщения: первое (с построением туннеля) и по установленной сессии |
| `relay_failure.csv`, `relay_freeze.csv` | отказ ретранслятора (kill) и его зависание (freeze) |
| `bootstrap_shutdown.csv` | lookup после отключения bootstrap-узла |
| `cluster_events.json` | события оркестратора: запуск, kill, restart |
| `node_logs.zip` | журналы и выгрузки всех узлов, конфигурации (`configs/`); закрытых ключей нет |
